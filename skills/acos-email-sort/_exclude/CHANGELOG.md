# Changelog

All notable changes to this skill are documented here, newest first.

## 0.6 — 2026-09-24

Sanitization pass ahead of org-wide distribution. `SKILL.md` hardcoded a real internal address, `accounts_payable@thesignatry.com`, in two places; both now point at `config.json`'s existing `accounts_payable_address` field, which already holds it. Behaviour is unchanged and the skill stops carrying one organization's address in its shipped body.

Three provenance attributions naming the owner directly ("confirmed by Trevor, 2026-08-12") are now "confirmed with the owner" — the dated rationale and its `_exclude/` report reference stay exactly where they were, only the personal attribution changed. `SKILL.md` is the file Claude loads into context, so a colleague installing this skill no longer reads another person's name as the implied default user.

The five files under `state/` (config, ledger, run summaries, bulk-review snapshot) are no longer shipped in the packaged zip; `state/run_history.jsonl` had also been committed to git for six commits, because the ignore rule read `state/*.json` and missed the `.jsonl` extension. Both are fixed at the repo level.

Thirteen further passages in `scripts/triage.py` that named the owner directly, including two that carried gendered pronouns ("a reply only he can give", "his own placement there"), now read "the owner" and "they". These are comments and docstrings, so nothing about classification behaviour changed — but the file ships to every beta tester, and a colleague installing the skill should not read one person's name as the implied default user.

`references/rejection_templates.yaml`'s header comment was rewritten: 77 lines of prose down to 50, with the per-template history moved here and the trust signal promoted from prose into data. Every template now carries a `provenance:` key — `real` for copy from a decline the owner actually sent, `drafted` for invented copy written to close a coverage gap — so the distinction survives as entries are added instead of living in a paragraph that has to be kept in sync. Four are `real` (`cybersec_msp_pitch`, `contact_list_data_pitch`, `staffing_recruiting_pitch`, `software_dev_partnership_pitch`) and four are `drafted` (`nonprofit_outreach_pitch`, `email_verification_probe`, `conference_event_meetup_pitch`, `generic_vendor_demo_pitch`). The header also now states what was previously only implicit: this file is read-only to the skill and ships inside the packaged zip, so a local edit is overwritten on the next upgrade. New templates and pattern fixes go to techsupport.thesignatry.com to be incorporated centrally and shipped in the next release, which closes one person's coverage gap for every beta tester rather than one mailbox. SKILL.md's run summary gained a matching recommendation bullet: when a pitch shape keeps hitting the fallback topic or falling through to `undetermined`, describe it, suggest a topic name, and point the owner at that channel — never edit the file. Verified no functional change — all eight templates parse with identical match patterns, subject prefixes, HTML bodies and disclosure footer.

The history that header carried, recorded here instead:

- The four `real` templates were lifted on 2026-08-02 from the owner's own filed decline drafts under `_watch/Vendors/…/Not Interested/{CyberSec, List, Staffing, SW_Dev}`, with match patterns built from the vendor emails filed alongside each one.
- `nonprofit_outreach_pitch` (2026-08-10) was the first invented template, added after a recurring "for your nonprofit" cold-outreach shape appeared across several unrelated pitches with no single prior reply to source from. Its patterns deliberately avoid a bare "nonprofit" keyword, which is core Signatry vocabulary and appears constantly in legitimate donor, grant and internal mail; they match only the outward-facing "for/prepare your nonprofit" phrasing a cold vendor uses.
- `email_verification_probe` and `generic_vendor_demo_pitch` (2026-08-12, Theme C) closed a gap the Stage 2 test found: eight cold pitches hand-filed as declines matched no template and fell through to `undetermined`.
- `conference_event_meetup_pitch` (2026-08-17) covers a vendor asking whether the owner will attend a named conference and proposing to meet there. It deliberately does not match specific conference names, which vary every time, only the "will you be there / let's meet up" framing.
- Marketing review remains outstanding for the four `drafted` templates, the regex coverage most of all, since it is a first pass over a small sample.

`_exclude/stage2_accuracy_report.md` and `_exclude/stage3_accuracy_report.md` were removed. The 0.1 entry above already carries their conclusions in full — headline accuracy numbers, all ten root-cause themes, what was implemented for each, the D/F/G follow-up round, and the two findings accepted rather than fixed — so what is lost is the per-message detail and the confusion matrix, not the reasoning. The 21 citations to them across `SKILL.md` and `scripts/triage.py` now point at this file instead, so every "Theme D" or "regression #3" reference still resolves. Both reports remain in git history if the per-message detail is ever needed again.

## 0.5 — 2026-08-17

Added a new decline template, `conference_event_meetup_pitch`, for a pitch shape the existing six didn't cover: a vendor asking whether the owner is attending a named conference/event and proposing to meet up there or stop by a booth. Deliberately doesn't try to match the conference's own name (varies every time) — only the surrounding "will you be there" framing. No `triage.py` code changes needed — decline-template matching is fully data-driven from `rejection_templates.yaml`, so a new entry there is picked up automatically by both the main Classify step and the `4_autorespond` sweep. Verified end-to-end (subject match, body-only match, `render-template`, and full `classify`) against synthetic test messages.

## 0.4 — 2026-08-17

Fixed a rendering bug in `cmd_render_template` found during a live morning-plan run: the four decline templates that link `{personal_linkedin_url}` as its own visible link text (`<a href="{personal_linkedin_url}">{personal_linkedin_url}</a>`) rendered a blank, hrefless `<a></a>` whenever that field was empty (e.g. an owner who hasn't filled in `acos-aboutme`'s `owner.linkedin_url` yet), rather than degrading gracefully. Now drops the whole parenthetical sentence fragment when the URL is unset instead of rendering broken markup.

## 0.3 — 2026-08-16

Config/profile centralization pass, following an evaluation of overlap between this skill's local `state/config.json` and `acos-aboutme`'s shared profile. Hardened the EA lookup in `merge_aboutme()`: `ea_name`/`ea_email` now resolve via `acos-aboutme`'s new explicit `staff[].is_executive_assistant` flag instead of a substring match on freeform `role` text, which was one bad title string away from silently breaking. Removed the dead `home_timezone` field from `config.example.json` (confirmed nothing reads it). Genericized two output strings in `triage.py` that named this organization or a specific vendor by name. Completed the `SKILL.md` wording pass (frontmatter description plus every body mention) and fixed one leftover generic-reusability phrase in `rejection_templates.yaml`'s header comment — historical provenance notes citing specific real filenames/dates (e.g. where the original decline drafts were pulled from) were deliberately left as-is, same treatment as the `(confirmed by Trevor, <date>)` citations kept in `SKILL.md`.

## 0.1 — 2026-08-02

Initial build: the `_claude/*` folder taxonomy (`1_priority` through `7_toBeFiled`), the deterministic classify/decline/move flow in `triage.py`, and the manual-Outlook-folder-creation gate. Delegate criteria confirmed 2026-08-10: the EA handles scheduling/calendar coordination and travel logistics; non-travel invoices/receipts and general AP requests stay with the mailbox owner.

**2026-08-12 — Stage 2/Stage 3 accuracy testing** (the two full reports were removed in 0.6; this entry is now the record): a 281-message real-mailbox comparison (Stage 2) found 36.7% exact-match accuracy against how mail was actually filed by hand (68.4% "functionally acceptable" once harmless bulk/file-boundary disagreements are folded in), with ten root-cause themes identified (A–J). Same-day Stage 3 testing implemented fixes for most of them and re-measured: exact match rose from 37.1% to 52.2% (278-message basis), and high-severity mismatches (crossing the `1_priority` boundary) fell from 26 to 16. Implemented: Theme B (internal/operational-alert senders route to `2_review` ahead of the bulk-mail check, with calendar/OOO artifacts explicitly excluded after a same-day regression); Theme C (decline-template matching expanded for common cold-pitch/verification-probe shapes); Theme D (`score_priority` restructured so the VIP-sender signal survives calendar/OOO suppression except for pure RSVP prefixes, plus new sender-independent financial-document/deal-document/HR-lifecycle priority keywords); Theme E (content-based `personnel_content_keyword_patterns`, independent of sender domain); Theme F (a `routine_notification` bucket for recurring payroll/meeting-reminder boilerplate); Theme G folded into Theme D's deal-document keywords; Theme H documented (`4_autorespond` reframed as a manual decline-landing zone matching how it's actually used, not a transient retry-only state); Theme J (a deterministic `ea_scheduling_delegate` check ahead of `protected_contact`). A same-day high-severity follow-up round (Groups D/F/G) added `personal_action_request_keyword_patterns`, a paired vendor-name + `vendor_onboarding_keyword_patterns` check, and two sender-exclusion allowlists (`financial_document_excluded_senders`, `urgent_keyword_excluded_senders`). Two findings were accepted as-is rather than fixed: the `6_bulkToReview`/`7_toBeFiled` boundary (Theme A, monitored instead of merged) and a split-verdict "termination" keyword case, which needs case-by-case human judgment the test data couldn't supply.

**2026-08-13:** `record-run` / `state/run_history.jsonl` added so `acos-main`'s month-retro has durable per-run email-volume history to read.
