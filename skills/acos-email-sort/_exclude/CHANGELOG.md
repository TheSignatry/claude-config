# Changelog

All notable changes to this skill are documented here, newest first.

## 0.3 — 2026-08-16

Config/profile centralization pass, following an evaluation of overlap between this skill's local `state/config.json` and `acos-aboutme`'s shared profile. Hardened the EA lookup in `merge_aboutme()`: `ea_name`/`ea_email` now resolve via `acos-aboutme`'s new explicit `staff[].is_executive_assistant` flag instead of a substring match on freeform `role` text, which was one bad title string away from silently breaking. Added `{personal_linkedin_url}`, `{careers_url}`, `{company_linkedin_url}` placeholders to `cmd_render_template` and updated `rejection_templates.yaml`'s decline templates to use them instead of hardcoded URLs — `personal_linkedin_url` sources from `acos-aboutme`'s new `owner.linkedin_url` when present (a genuine identity fact, now centralized), while `careers_url`/`company_linkedin_url` stay local-only in `config.example.json` since they're specific to how this skill's decline templates handle recruiting pitches, not general org-chart data. Removed the dead `home_timezone` field from `config.example.json` (confirmed nothing reads it). Genericized two output strings in `triage.py` that named this organization or a specific vendor by name. Completed the `SKILL.md` wording pass (frontmatter description plus every body mention) and fixed one leftover generic-reusability phrase in `rejection_templates.yaml`'s header comment — historical provenance notes citing specific real filenames/dates (e.g. where the original decline drafts were pulled from) were deliberately left as-is, same treatment as the `(confirmed by Trevor, <date>)` citations kept in `SKILL.md`.

## 0.1 — 2026-08-02

Initial build: the `_claude/*` folder taxonomy (`1_priority` through `7_toBeFiled`), the deterministic classify/decline/move flow in `triage.py`, and the manual-Outlook-folder-creation gate. Delegate criteria confirmed 2026-08-10: the EA handles scheduling/calendar coordination and travel logistics; non-travel invoices/receipts and general AP requests stay with the mailbox owner.

**2026-08-12 — Stage 2/Stage 3 accuracy testing** (see `_exclude/stage2_accuracy_report.md`, `_exclude/stage3_accuracy_report.md`): a 281-message real-mailbox comparison (Stage 2) found 36.7% exact-match accuracy against how mail was actually filed by hand (68.4% "functionally acceptable" once harmless bulk/file-boundary disagreements are folded in), with ten root-cause themes identified (A–J). Same-day Stage 3 testing implemented fixes for most of them and re-measured: exact match rose from 37.1% to 52.2% (278-message basis), and high-severity mismatches (crossing the `1_priority` boundary) fell from 26 to 16. Implemented: Theme B (internal/operational-alert senders route to `2_review` ahead of the bulk-mail check, with calendar/OOO artifacts explicitly excluded after a same-day regression); Theme C (decline-template matching expanded for common cold-pitch/verification-probe shapes); Theme D (`score_priority` restructured so the VIP-sender signal survives calendar/OOO suppression except for pure RSVP prefixes, plus new sender-independent financial-document/deal-document/HR-lifecycle priority keywords); Theme E (content-based `personnel_content_keyword_patterns`, independent of sender domain); Theme F (a `routine_notification` bucket for recurring payroll/meeting-reminder boilerplate); Theme G folded into Theme D's deal-document keywords; Theme H documented (`4_autorespond` reframed as a manual decline-landing zone matching how it's actually used, not a transient retry-only state); Theme J (a deterministic `ea_scheduling_delegate` check ahead of `protected_contact`). A same-day high-severity follow-up round (Groups D/F/G) added `personal_action_request_keyword_patterns`, a paired vendor-name + `vendor_onboarding_keyword_patterns` check, and two sender-exclusion allowlists (`financial_document_excluded_senders`, `urgent_keyword_excluded_senders`). Two findings were accepted as-is rather than fixed: the `6_bulkToReview`/`7_toBeFiled` boundary (Theme A, monitored instead of merged) and a split-verdict "termination" keyword case, which needs case-by-case human judgment the test data couldn't supply.

**2026-08-13:** `record-run` / `state/run_history.jsonl` added so `acos-main`'s month-retro has durable per-run email-volume history to read.
